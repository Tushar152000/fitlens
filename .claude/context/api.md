# apps/api — NestJS backend (the only backend)

Paths relative to `apps/api/`. Facts from the code, not docs. Known bugs live in `risks.md`.

## Plumbing (every route)

- `src/main.ts`: prefix `/api`, `trust proxy` 1, helmet, cookie-parser, 1 MB JSON, CORS always for `PUBLIC_URL` origin + `CORS_ORIGINS`, with credentials (the web calls the API directly). `src/worker.ts` = same AppModule, no HTTP, `APP_ROLE ??= "worker"`.
- Guards in order (`src/app.module.ts:87-92`): Throttler (60 s window; `@StrictRateLimit` = `AUTH_RATE_LIMIT` 20, else 300/IP/route; in-memory per process) → `OriginGuard` (CSRF: cookie + state-changing needs Origin = `PUBLIC_URL`/`CORS_ORIGINS` or `Sec-Fetch-Site` same-origin; bearer exempt) → `AuthGuard` (session required unless `@Public()`; sets `req.auth={userId,sessionId}`).
- Handlers get the user via `@UserId()` / `@CurrentAuth()` (`src/common/auth/decorators.ts`). Services take `userId` first and must filter by it; foreign rows → `notFound()` 404.
- Errors: `AllExceptionsFilter` → `{error, details?}`; `AppError` status kept; `ZodError` → 400; unknown → 500 (Prisma P2002/P2025 are NOT mapped → 500).
- Validation: `@ZodBody`/`@ZodQuery` with `@fitr8/contracts`. Path params and several queries (`date`, `q`, `days`) are NOT validated.
- Logging: nestjs-pino, `x-request-id` in/out; logs url incl. query string.
- Config: only `src/config/env.ts` reads env (zod); `@InjectEnv()`. `APP_ENV` local|test|staging|production (defaults from NODE_ENV). `isDeployed(env)` = staging|production.

## Auth (`modules/auth`)

- Opaque 256-bit token, only SHA-256 stored (`session.service.ts`). Web: httpOnly SameSite=Lax cookie (`auth.cookies.ts`): with `AUTH_COOKIE_DOMAIN` (prod `.fitr8.com`) `__Secure-fitlens_session; Domain=…`, else `__Host-fitlens_session` (https) / `fitlens_session` (http). Secure is decided by `API_PUBLIC_URL`. App: `Authorization: Bearer` (wins if both). No JWT, no refresh token, no rotation.
- Idle expiry `SESSION_DAYS` 30 web / `MOBILE_SESSION_DAYS` 90 app, slid at most once a day, hard cap `SESSION_MAX_DAYS` 365 (`auth.policy.ts`).
- Google redirect URI = `API_PUBLIC_URL/api/auth/callback/google` (`auth.service.ts` `googleRedirectUri`); after sign-in users go to `PUBLIC_URL` paths.
- Google: PKCE S256 + state + nonce sealed (AES-256-GCM, HKDF from `AUTH_SECRET`) in a 10-min cookie on `/api/auth`; ID token verified via JWKS. Mobile hand-off: one-time hashed code in `auth_codes`, 2 min, bound to app challenge; redirect must be `fitlens:` (`exp:` only when not deployed).
- Apple: native iOS identity token via Apple JWKS, aud = bundle id, nonce = sha256(raw). Refresh token sealed into `auth_identities.refreshTokenSealed` when team/key configured, revoked on account delete.
- Identity linking (`identity.service.ts`): by (provider, subject); new subject links to existing user only by verified email and if that user has no other identity at the same provider. Apple CAN link to a Google account by email.
- `AuthCleanupService` (hourly: expired sessions/codes, events > 90 d) is skipped when `APP_ROLE=api` or test.

## Billing / Pro (`modules/billing`, rules in `packages/domain/src/billing`)

- `entitlements` row per user; Pro = `lifetime` or `proUntil > now`.
- Webhook: auth → zod → dedupe by event id (`billing_events`) → candidate ids (cuid-shaped only) → with `REVENUECAT_SECRET_KEY`: re-read subscriber via REST (failure 502 → RevenueCat retries); without: `accessFromEvent` applied if newer than `syncedAt` (TRANSFER skipped).
- Limits `dailyLimits(plan, paywall)`: PRO 30 scans / 40 coach / labels; FREE+paywall off 3 / 40 / labels; FREE+paywall on 3 / 5 / no labels. `PAYWALL_ENABLED` default false; deployed + paywall requires both RevenueCat secrets.
- Scans = count of `AiCall.countsAsScan` since local midnight (`meals/scan-quota.service.ts`); checked before the AI call (race with queued jobs). Text cap 60/day hidden (not in docs).
- Coach cap counts `coach_messages` with `role:"user"` (`coach/coach.service.ts:66`) — includes tool_result rows (bug, see risks).

## AI

- `AI_PROVIDER` mock (default) | anthropic | openai; key required for the chosen one. Default models: `claude-opus-5-5` / `gpt-6.1-sol` (override `AI_EXTRACTION_MODEL`, `AI_COACH_MODEL`); `AI_COACH_EFFORT` medium. Clients: 3 retries, 120 s timeout.
- Extraction port `FOOD_EXTRACTOR` (`ai/extraction/`): Claude uses `beta.messages.parse` + zod output, low effort, cached system prompt, server-side refusal fallback; OpenAI uses Responses API json_schema + zod re-validate. Prompts in `prompts.ts` (Indian household units).
- Meal pipeline `meals/meal-analysis.job.ts`: load log → in parallel {status ANALYZING, 90-day frequent foods, photo bytes from storage} → model → in parallel {AiCall row, price items} → one transaction (items + READY). Not food → FAILED, no scan. Logs `meal analysed` with stage ms (`load`, `prepare`, `model`, `price`, `save`, `totalMs`, `matched`/`items`) — use Cloud Run logs to see where time goes. BullMQ (3 attempts) when `REDIS_URL`, else inline in the POST /meals request (prod: inline).
- Food matching `meals/meal-items.service.ts` `pickFood`: one query, then exact name/alias → longest DB name that ENDS the detected name ("tandoori roti"→"roti"; "ghee rice"≠"ghee") → a DB name ending with the detected name only if unique ("chai"→"masala chai"; "coffee" with 4 coffees → no match). Only generic foods (`barcode: null`, no unreviewed label scans). No match → model's per-100 g estimate, `approximate: true`. Matched foods with a known unit replace the model's grams with unit grams × quantity.
- Coach (`modules/coach`): `agent/agent-loop.ts` manual streaming loop, max 8 iterations (last forces `tool_choice: none`), tools run in parallel, zod-validated; step persisted atomically (assistant turn + its tool_results). Gateways: `claude.gateway.ts` (stream, compaction beta, top-level cache_control, effort), `openai.gateway.ts` (translates transcript; no compaction; `prompt_cache_key`). Tools (`coach/tools/coach-toolbox.ts`): get_today_overview, get_history, get_progress, get_workout_today, search_foods, log_water, log_weigh_in, draft_meal — userId bound in closure. Turn lock: Redis `SET NX PX 3min`, else in-process Map. Each model call writes an `AiCall` COACH_CHAT row.

## Storage (`infra/storage/storage.service.ts`)

S3/R2/MinIO client. Presigned PUT 300 s, binds ContentType only (no size limit). Presigned GET 600 s default (300 meal detail, 3600 dashboard). `getImage` buffers whole object then rejects > 10 MB. Bucket auto-created only when not deployed. Photos deleted only on account delete (`deleteUserPhotos`).

## Env (all in `src/config/env.ts`)

Runtime `NODE_ENV APP_ENV APP_ROLE(all) PORT(4000) LOG_LEVEL PUBLIC_URL(web origin) API_PUBLIC_URL(default PUBLIC_URL) AUTH_COOKIE_DOMAIN CORS_ORIGINS` ("" = unset for the new two) · Data `DATABASE_URL(req) DATABASE_POOL_MAX(10) REDIS_URL` · Auth `AUTH_SECRET(req ≥32) AUTH_GOOGLE_ID/SECRET APPLE_CLIENT_ID/TEAM_ID/KEY_ID/PRIVATE_KEY AUTH_DEV_LOGIN SESSION_DAYS MOBILE_SESSION_DAYS SESSION_MAX_DAYS AUTH_RATE_LIMIT` · Storage `S3_*` · AI `AI_PROVIDER ANTHROPIC_API_KEY OPENAI_API_KEY AI_EXTRACTION_MODEL AI_COACH_MODEL AI_COACH_EFFORT AI_DAILY_LIMIT(3) COACH_DAILY_LIMIT(40) AI_PRO_DAILY_LIMIT(30) COACH_FREE_DAILY_LIMIT(5)` · Billing `PAYWALL_ENABLED REVENUECAT_WEBHOOK_AUTH REVENUECAT_SECRET_KEY REVENUECAT_ENTITLEMENT(pro)` · `OFF_CONTACT`.
Deployed refuses: dev login on, missing Google creds, partial Apple config, non-https `PUBLIC_URL`/`API_PUBLIC_URL`, paywall without RevenueCat secrets. Always refuses: web and API on different hosts without `AUTH_COOKIE_DOMAIN`, or a domain not covering both.

## Layering reality

Module-owns-its-tables (ARCHITECTURE §3.2) is broken widely: users writes profiles; plan writes body_metrics; labels/coach write ai_calls; water/workouts/dashboard/history/progress read meal_logs/profile/goals directly. `checkins` and `exercises` tables are unused (exercises come from `@fitr8/domain` `EXERCISE_BY_SLUG`). Weekly adjustment "added in week 5" (`progress/checkins.service.ts:12`) not implemented.
