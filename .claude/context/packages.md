# packages — domain, contracts, db

## @fitr8/domain (`packages/domain/src`, pure, zod only)

Subpath exports (`package.json`): `./nutrition ./training ./dates ./format ./barcode ./label ./billing ./reminders`, resolved from `dist/` (build first; turbo `^build` handles it).

- **nutrition/**: `body.ts` (ACTIVITY_FACTORS, `bmi`, `bodyFatNavy` (null on invalid / outside 2–70%), `bmr` Mifflin-St Jeor, `tdee`, `ageFromBirthDate` uses local-time getters); `macros.ts` (`macrosFor`: protein 1.8 g/kg fat loss else 1.6; fat max(25% kcal, 0.6 g/kg); carbs remainder ≥0 — can exceed kcal for heavy users at floor; `scaleNutrition`, `sumMacros`); `goal.ts` (`KCAL_PER_KG_FAT` 7700, floor 1500 M / 1200 F, `LIMITS`, `resolveTargetWeight`, `planGoal` → targets, feasibility, `suggestedTargetDate`, `closerTargetWeightKg`; under-18 or medical flag → no adjustment); `water.ts` (`waterTarget` 33 ml/kg + activity + 500 training, clamp 1500–4500); `preview.ts` (`previewTarget`, `PREVIEW_WEEKS` 12, `PREVIEW_PACE_PCT`) — web landing only.
- **training/**: `types.ts` (`WeekPlanSchema` = `WorkoutPlan.plan` JSON shape), `dose.ts` (`caloriePhase`, `doseFor`, `isDeloadWeek`), `split.ts` (`splitFor`, `exercisesFor`, `REST_SEC`), `library.ts` (61 `EXERCISES`, `EXERCISE_BY_SLUG`, `ruledOutByInjury`), `progression.ts` (`startingLoad`, `nextTarget` double progression), `plan.ts` (`buildWeek`), `adjust.ts` (`adjustSession`, `fuelStatus`, `pickSnack`), `fuel.ts`, `checkin.ts` (`reviewTraining` — not wired to any app).
- **billing/index.ts**: `isPro`, `planOf`, `dailyLimits(plan, paywall, cfg)`, `accessFromEvent(event, entitlementId)`.
- **dates.ts**: `localDate(tz='Asia/Kolkata')`, `parseDateOnly` (Invalid Date on bad input), `weekStart` (Monday), `startOfLocalDay`, `MEAL_BACKFILL_DAYS` (7) + `mealDateProblem(date, today)` (meal backfill window, tested).
- **reminders.ts**: reminder rules as cron with extensions (`parseRule`/`parseRules`: one minute; hour list/range/step; day-of-month dates, `L`, `L-n`; weekday lists/names, `d#n`, `dL`; month lists/names; dom and dow not both). `isRepeating` (all months + weekdays, or fixed dates ≤ 28) → `scheduleSlots` (daily/weekly/monthly); else `upcomingTimes(rule, now, 3)` on wall-clock dates (`LocalDateTime`, `formatLocal`). `describeRule`/`describeRules`, `toCron` canonical, `ordinal`, `formatClock`. Caps: 24 repeating alerts per reminder, 6 rules, 4 times/day on changing dates, 20 reminders. Tested (20).
- **activity.ts** (export `./activity`): `WELCOME_BACK_AFTER_DAYS` 90, `ACTIVITY_TOUCH_MS` 1 h, `isWelcomeBack({onboardedAt,lastActiveAt}, now)` (falls back to onboardedAt; never before onboarding), `shouldTouchActivity` (never while welcome back is pending). Tested (8).
- **format.ts**, **barcode.ts** (GS1, UPC-E→A, `normalizeBarcode`), **label.ts** (`labelAddsUp`).
- Tests: nutrition, preview, water, training, billing, barcode, label, reminders, person. Untested exports include `bmiCategory`, `ageFromBirthDate`, `sumMacros`, `parseDateOnly`, `ruledOutByInjury`, `roundToStep`, `estimateMinutes`, several format helpers (ARCHITECTURE's "100% tested" is false).

## @fitr8/contracts (`packages/contracts/src`, zod 4)

- `requests.ts` (`MealItemInputSchema` shared by ConfirmMeal + SavedMeal; SavedMeal, LogSavedMeal, Reminder, ReminderUpdate, ReminderParse; meal bodies CreateMeal/Relog/QuickAdd/LogItems/LabelSave take optional `date`): Onboarding, UploadUrl, CreateMeal (PHOTO/TEXT/MANUAL), ConfirmMeal, Recheck, Checkin, ParseItems, Relog, GoalOption, Reminders, PreferredName (name + optional lastName/phone; phone transformed to E.164 with domain `normalizePhone`, `requests.ts:141`), WaterAdd, QuickAdd, LabelScan, LabelSave, Energy, WorkoutLog, LogItems, ContactMessage (website contact form: name 1–100 with no line breaks, email, message 10–`CONTACT_MESSAGE_MAX`=2000, optional honeypot `website`).
- `auth.ts` (GoogleStartQuery, MobileStartQuery, MobileToken, AppleSignIn, DevLogin; ProvidersDto, AuthTokenDto, SessionDto), `billing.ts` (RevenueCatWebhookSchema passthrough, BillingDto), `coach.ts` (CoachChatSchema, CoachStreamEvent), `ai.ts` (MealAnalysisSchema, LabelReadSchema, ReminderDraftSchema), `responses.ts` (all DTOs, `Jsonify`), `analytics.ts` (type-only `AnalyticsEvents` map shared by web + app GA; `export type *`).
- Loose spots: `OnboardingSchema.timezone` any string (invalid IANA → 500); `ConfirmMealSchema.items` no max; `mealAnalysisJsonSchema`/`labelReadJsonSchema` unused. No tests in this package.

## @fitr8/db (`packages/db`)

- Prisma 7, `prisma-client` generator, ESM, output `src/generated/prisma` (gitignored; run `pnpm db:generate` after schema changes). `src/index.ts` exports `createPrismaClient` (PrismaPg).
- Schema `prisma/schema.prisma` — tables: users (`lastActiveAt`, migration `20261117120000_user_last_active` backfills from sessions/meals/body metrics/water/workouts/profiles), auth_identities, sessions, auth_codes, auth_events, profiles, goals, daily_targets (append-only history), body_metrics (unique userId+date), foods (unique name, unique barcode, `verified`, `submittedById` no FK), barcode_misses, label_scans, food_units, meal_logs (status PENDING→ANALYZING→READY→CONFIRMED|FAILED), meal_items, exercises (unused by API), workout_plans (unique userId+weekStart+version), workout_logs (no unique), checkins (unused), ai_calls, water_logs, saved_meals + saved_meal_items (position-ordered, food FK SetNull), reminders (`crons String[]` + enabled + prompt), coach_conversations, coach_messages (append-only `content` JSON), entitlements, billing_events.
- All user-owned tables cascade on user delete; ai_calls SET NULL. No soft deletes.
- Migrations (13, latest `saved_meals_reminders`: 3 tables + AiCallType `REMINDER_PARSE`; before it `foreign_key_indexes`: indexes on auth_codes.userId, daily_targets.goalId, meal_items.foodId, workout_logs.planId). `pnpm db:drift` (needs `SHADOW_DATABASE_URL`) proves migrations == schema; CI runs it.
- Earlier migrations (11): init → meal note/liquids → scan quota → reminders → barcode foods → exercise library → water → coach agent → auth_sessions (irreversible; replaced Auth.js tables) → apple sign-in → pro entitlements. Schema matches final migration (manual check).
- `prisma/seed.ts`: 32 placeholder foods (header says replace with IFCT/INDB before launch) + exercises mirror. Seed in prod is a manual Cloud Run job execution.
- `@fitr8/domain/person` (`src/person.ts`): `normalizePhone` (bare 10-digit → +91), `formatPhone`, `PHONE_COUNTRIES` (36, IN first), `flagEmoji`, `phoneToE164(iso, national)` (`:86`), `splitPhone` (`:103`, +1 → US), `personProblems` (`:127`), `splitName`, `PHONE_TAKEN` (`:115`). Contracts now import domain at runtime (requests.ts) — build domain before contracts.
- DB: `users.lastName`, `users.phone` (nullable, `@unique` — migration `20261118011500_unique_user_phone` clears duplicates first; columns from `20261117185447_onboarding_contact_details`); `profiles.medicalNote` (`20261118014000_profile_medical_note`). Contracts: `PhoneCheckQuerySchema`/`PhoneCheckDto`, `OnboardingSchema.medicalNote` (≤500), `ProfileDto.medicalNote`.
